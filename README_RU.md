# PRIMA CARGO — бот и Mini App в одном проекте

В папке находятся обычный Telegram-бот и Telegram Mini App. Mini App и бот используют одну SQLite-базу `prima_cargo.db`. Интерфейс запускается через `main.py`; обычный бот — отдельной командой через `bot.py`.

## Что лежит в папке

- `bot.py` — исходный Telegram-бот (чат, меню и администрирование).
- `main.py`, `index.html` — API и экран Mini App.
- 
- `requirements.txt` — библиотеки для обоих процессов.
- `.env.example` — образец настроек; его надо скопировать в `.env`.
- `.gitignore` — не даёт случайно добавить токен и базу в Git.

## Настройка Windows (локально)

Откройте PowerShell в этой папке и выполните по одной команде:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` в VS Code и замените `BOT_TOKEN` на токен BotFather, а `ADMIN_IDS` — на числовые Telegram ID администраторов через запятую. Не отправляйте токен в чат и не добавляйте `.env` в GitHub.

Для обычного тестирования установите `APP_ENV=development`. В одном окне PowerShell запустите бота:

```powershell
python bot.py
```

Во втором окне, также из этой папки, запустите веб-часть:

```powershell
.venv\Scripts\Activate.ps1
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Адрес `http://127.0.0.1:8000` виден только на вашем компьютере и сам по себе не откроется у Telegram-пользователей. Для локальной отладки можно временно дать HTTPS-туннель, но для реального использования потребуется постоянно работающий хостинг.

## Что означает HTTPS-сервер

Это компьютер в интернете, который постоянно включён и имеет защищённый адрес вида `https://...`. На него устанавливают Python, размещают `bot.py`, `main.py`, `run.py` и `index.html`, настраивают секреты и переносят базу. Когда хостинг выдаст HTTPS-адрес, в Telegram через `@BotFather` задают этот адрес для кнопки меню бота (Menu Button / Web App). GitHub — хранилище кода; один только GitHub Pages не запускает Python API и не читает файл базы.

На сервере задайте переменные окружения `BOT_TOKEN`, `ADMIN_IDS`, `DB_PATH` и `APP_ENV=production`. Если бот и веб-часть находятся в одном приложении/контейнере, запускайте оба процесса и указывайте один и тот же постоянный путь к базе данных. На разных контейнерах нужна общая база/том; две отдельные SQLite-копии не синхронизируются.

## Какие файлы загрузить в GitHub

Загрузите: `bot.py`, `main.py`, `run.py`, `index.html`, `requirements.txt`, `.env.example`, `.gitignore`, `README_RU.md`.

Не загружайте: `.env`, `prima_cargo.db`, папку `.venv`, `__pycache__`. Токен должен храниться только в секретах хостинга или локальном `.env`.

## Важно перед реальными клиентами

Проверка по коду заказа не связывает заказ с владельцем. Тот, кто знает чужой код, потенциально увидит статус. Пока не добавлена привязка заказа к Telegram-пользователю, используйте только коды, которые не угадываются, и не храните в статусах личные данные. Перед переносом существующей базы сделайте резервную копию. Текущая база на вашем ноутбуке сама в комплект не копируется.




## Размещение после загрузки в GitHub (пример: Render)

GitHub хранит файлы, а Render запускает их и выдаёт публичный HTTPS-адрес.

1. В Render создайте **New → Web Service**, подключите ваш GitHub-репозиторий и выберите ветку `main`.
2. Укажите **Build Command**: `pip install -r requirements.txt`.
3. Укажите **Start Command**: `python run.py`. Этот файл запускает бота и Mini App вместе.
4. В настройках сервиса добавьте переменные окружения: `BOT_TOKEN` (новый секретный токен), `ADMIN_IDS`, `APP_ENV=production`, `DB_PATH=/var/data/prima_cargo.db`.
5. Добавьте постоянный диск сервиса с точкой подключения `/var/data`. SQLite-файл будет храниться там и переживёт перезапуск. У Render обычная файловая система временная, а бесплатные Web Services засыпают после простоя; для постоянной работы бота и сохранения базы понадобится тариф/вариант с постоянно работающим сервисом и постоянным диском.
6. Нажмите **Deploy**. После успешного запуска Render покажет адрес `https://....onrender.com`.
7. В Telegram откройте `@BotFather` → `/mybots` → выберите бота → **Bot Settings → Menu Button**, задайте текст кнопки и вставьте полученный HTTPS-адрес.

Если заказов пока нет, бот создаст пустую базу при запуске. Если в старой базе есть заказы, её нужно отдельно и безопасно перенести на постоянный диск по пути `DB_PATH`; не добавляйте её в GitHub. Могу провести перенос отдельно, когда репозиторий и хостинг будут готовы.

Перед запуском замените старый токен, если он когда-либо попал в GitHub. Значение `APP_ENV` на хостинге обязательно должно быть `production`.
